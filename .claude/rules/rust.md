# Rust 実装ルール（`src-tauri/`）

Rust 側を触るときに従う。ロジックの中心は `src-tauri/src/main.rs` で、次の機能だけを別のファイルに分けてある。Docker 連携は `src-tauri/src/docker/`（`discovery.rs`, `tunnel.rs`）、1Password 連携は `src-tauri/src/onepassword.rs`、ログは `src-tauri/src/app_log.rs`、クリックで戻れる通知は `src-tauri/src/toast.rs`、仮想デスクトップは `src-tauri/src/vdesk.rs`、Redis への接続は `src-tauri/src/redis_client.rs`、SQLite のファイルは `src-tauri/src/sqlite_client.rs`、PostgreSQL への接続は `src-tauri/src/postgres_client.rs`、TablePlus の接続設定の読み取りは `src-tauri/src/tableplus.rs`、同期フォルダの検出と同期ファイルの書き込みは `src-tauri/src/sync_folder.rs`。テストでだけ使うものは `src-tauri/src/credits.rs`、`src-tauri/src/docs_consistency.rs`、`src-tauri/src/verify.rs`（`testing.md` を参照）。マニュアルのスクリーンショットの撮影は `src-tauri/src/screenshots.rs`（`screenshots` feature のときだけ入る。`testing.md` の「マニュアルのスクリーンショット」）。

## 秘密情報
- **パスワード / API キー**: `keyring`（Windows Credential Manager）で保存。各パスワード（MySQL / SSH パスフレーズ / SSH パスワード）は `save_*` フラグで keyring 保存 or 都度入力を選択可能。都度入力の場合、query 画面で接続前にモーダルプロンプトを表示。
- **1Password 連携（#80）**: `op` CLI（公式 Rust SDK が無いためサブプロセス起動）を**パスワードの初期取得・更新元**として使う。`src-tauri/src/onepassword.rs`。解決順は「プロンプト入力 → keyring → 1Password」で、op から取れた値は即 keyring に書き戻すため **op が呼ばれるのはマシン毎に 1 回**。接続毎に呼ばない設計にしているのは、Windows では呼び出し元プロセス単位で認証が要る＝毎回 Windows Hello が出るため。参照は `op://vault/item/field` 形式の文字列 1 本（`MySqlConfig.op_ref` / `SshConfig.op_passphrase_ref` / `op_password_ref`）で、秘密ではないので**同期対象**。AI の API キーは同期対象外なので参照を localStorage（`musql:ai:op-ref:<provider>`）に置き `ai_assist` の引数で渡す。コマンド: `op_available`（UI の出し分け）/ `op_read_secret`（設定画面の `1P` ボタン）/ `op_list_items`・`op_list_fields`（参照ピッカー `ui/op-picker.js`、settings と query の両ウィンドウで共有。`window.openOpPicker()` が `Promise<string|null>` を返す）。**`op item get` の応答には `value`（秘密値そのもの）が入るため、`OpField` / `RawField` に `value` フィールドを足してはいけない**（serde が未知フィールドを捨てることで WebView に渡らないことを保証している。`parse_fields_drops_secret_values` テストで固定）。アイテム一覧は `ITEM_CACHE` でセッション内キャッシュ（取得が数秒〜かかるため）。op 呼び出しは `spawn_blocking` + 90 秒タイムアウト、`CREATE_NO_WINDOW` でコンソール抑止。実 CLI を叩くテストは `#[ignore]` 付き（`cargo test -- --ignored`）。

- **ログファイル（#110）**: `src-tauri/src/app_log.rs`（`tauri-plugin-log`）。インストール版でも `%LOCALAPPDATA%\{identifier}\logs\muSQL.log` に書く（1MB でローテーション、2 世代保持。stdout へも出すのは dev 版だけ）。**ログに書いてはいけないもの: パスワード、パスフレーズ、API キー、SQL の本文、クエリ結果、クエリの実行エラー**（MySQL はエラー文に SQL の一部を入れる）。`Err` を `log::warn!` してよいのは、**文を実行する前の段階の失敗だけ**（接続、SSH、同期、アップデート、AI の HTTP エラー、op CLI の stderr、keyring）。`run_query` などの文を実行した結果の `Err` に `inspect_err` を足さないこと。panic はメッセージを書かず発生位置だけを書く（`unwrap` のメッセージに MySQL のエラーや行データが入りうるため）。同じ状態で繰り返し起きる失敗（フォーカスのたびに走る同期の取り込み、タブ内の全クエリが落ちる接続断、キー入力ごとの AI 補完）は `log::warn!` ではなく `app_log::warn_throttled` を使う（同じ文を一定時間 1 回に間引く。間引かないとローテーションで他の行が押し出される）。マニュアル（`docs/manual/settings.md`「ログ」）が「記録しません」と約束している。Store 版（MSIX）は `%LOCALAPPDATA%` への新規書き込みが `…\Packages\<パッケージ>\LocalCache\Local\…` へ振り替えられるので、「ログフォルダを開く」は `app_log_dir` ではなく `real_log_dir`（`canonicalize` で実際の場所を引く。#124）を開く。パッケージの外にいる Explorer には振り替え前のパスが空に見えるため。プロファイルなど他のアプリデータも同じ振り替えを受ける。多重起動した全インスタンスが同じファイルへ追記する（行が混ざる、ローテーションが遅れることを許容している）。

## 接続
- **接続プール**: `ConnectionCache`（`Arc<Mutex>`）で query 画面の接続（`Backend`。MySQL は Pool、SQLite はファイルのパス、PostgreSQL はサーバーとデータベース）と SshTunnel をキャッシュ。fingerprint 一致で再利用。
- **クエリキャンセル**: `RUNNING_QUERIES`（`RunningQueryEntry`）でタブ単位に止める。MySQL は `KILL QUERY`、SQLite は `InterruptHandle`、PostgreSQL は接続の `CancelToken`。
- **接続の種類（#132）**: `ConnectionRequest.engine`（`Engine` enum、保存形式は `mysql` / `mariadb` / `redis` / `sqlite` / `postgresql`。無ければ `mysql`）。種類ごとの振る舞い（開く画面、MySQL として接続できるか、接続テストの方法）は、すべて `Engine::protocol`（`Protocol::Mysql` / `Protocol::Redis` / `Protocol::Sqlite` / `Protocol::Postgres`）から決める。種類を足すときは `protocol` に足す。**接続先の項目は、どの種類でも `mysql` のキー（`MySqlConfig`）に置く**。種類ごとにキーを分けると、それより古い版は `mysql` が無いプロファイルを 1 件読んだだけで、`connections.json` も同期ファイルも全体が読めなくなるため。古い版はすべてを MySQL として一覧に出し、MySQL 以外は開いたときに失敗する。**古い版がローカルの `connections.json` を保存し直すと、`engine` は落ちて MySQL に戻る**（古い版は知らないフィールドを読み捨てる）。同期ファイルは、新しい版が書いたものへの古い版の書き込みが止められる（`sync_file_written_by_newer`、#81）ので、同期している他のマシンには広がらない。`Unknown` が綴りを保つのは、`engine` を知っている版どうしの話である。種類に固有の項目は `MySqlConfig` に任意の項目として足す。未知の種類は綴りを保ったまま `Unknown` として読み、開く画面を持たない（`Engine::window`）。MySQL として接続しない（`Engine::ensure_mysql_protocol`）。開く画面は `open_connection_window` が種類から決める。AI プロンプトの名前は接続のキャッシュ（`ConnectionCache.engine`）から取る。画面側の表示名（`ui/app.js` の `ENGINE_NAMES` と、`ui/settings.html` の DB Engine の選択肢）は `Engine::display_name` と揃える。`ui/settings.js` の `ENGINE_FIELDS`（種類ごとの既定のポートやユーザー）にも、すべての種類を載せる（テスト `ui_engine_names_match_the_engines` がこの 3 か所を照合する）。種類を足すときは、テストの `known_engines` にも足す。
- **Redis（#98）**: `src-tauri/src/redis_client.rs`。接続先は他の種類と同じ `MySqlConfig` に置き、`username` は ACL のユーザー（空なら既定のユーザー）、`database` は DB 番号（空なら 0）として読む。SSH トンネルと資格情報の解決は MySQL と共用し、最後の接続だけが違う（`run_connection_test` は `Engine::protocol` で分ける）。接続を待つ時間は SSH と同じ `CONNECT_TIMEOUT`。SSL モードは MySQL と同じ意味で TLS に対応させる（`REQUIRED` は証明書を検証しない、`VERIFY_CA` はホスト名を検証しない、`VERIFY_IDENTITY` は両方を検証する）。**TLS は rustls を使う**（native-tls の構成では独自の CA 証明書を渡せないため）。**rustls の暗号プロバイダー（`ring`）は `Cargo.toml` で直接有効にしている**。更新機能（reqwest）経由でも有効になるが、更新機能を外した Store 版では何も有効にならず、TLS の接続が実行時に失敗するため。この依存を外さないこと。Redis の画面の接続は `RedisSession`（`RedisState` で 1 本だけ持つ）。タイムアウトや切断のあとは状態が分からないので接続を捨て、次の呼び出しで張り直す。CLI の SELECT と DB の切り替え（`redis_select` → `RedisSession::select`）で選んだ DB は `RedisSession` が覚え、張り直した接続でも選び直す（黙ってプロファイルの DB に戻らないように）。CLI（`redis_client::command`）は、サーバーのエラー（型違いなど）を `(error) ...` という出力として返し、接続の失敗だけを `Err` にする。**危険なコマンドの判定は Rust で行う**（`DANGEROUS_COMMANDS` / `DANGEROUS_SUBCOMMANDS`。`split_command` で引用符を解いたあとの名前で見るので、`"FLUSHALL"` と書いても確認をすり抜けない）。確認していない呼び出しには実行せずに `confirm` を返し、画面が確認してから `confirmed: true` で送り直す。画面側でコマンドの文字列を解釈しないこと。`SUBSCRIBE` / `MONITOR` など接続を待ち受けにするコマンド（`STREAMING_COMMANDS`）と、`MULTI` / `RESET` など接続の状態を変えるコマンド（`STATEFUL_COMMANDS`。CLI はキーの一覧やキーのタブと接続を共有するため）は断る。CLI の引数はバイト列で扱う（`\xHH` を 1 バイトにするため）。キーの一覧とキーのタブに出すキー名と値は、UTF-8 で制御文字を含まなければそのまま、それ以外（バイナリ）は `escape` の表記で表示する（`as_text`、`shown`。値はタブと改行を制御文字に数えないが、キー名は一覧で 1 行に出すので数える）。`escape` は redis-cli の表記に倣い `\xHH`、`\n`、`\\`、`\"` などで書くが、読める UTF-8 の文字はそのまま残す（redis-cli は 0x7f 以上のバイトをすべて `\xHH` にする。合わせると日本語が読めなくなる）。CLI の応答は redis-cli と同じく常に `"..."` で囲んで `escape` する。キー名と値の表示に `from_utf8_lossy` を使わないこと（読めないバイトが U+FFFD になり、元のバイトが分からなくなる）。キー名はバイト列のまま扱う。一覧（`KeyEntry`）は表示用の名前を返し、バイナリのキーには元のバイト列の hex（`raw`）も付ける。画面は `raw` を `redis_key` に返す（`key_bytes`）。表示用の名前で開き直さないこと（別のキーを指す）。`redis_connect` は、接続を張っている間に閉じられたり開き直されたりしたら、セッションを保存しない（`redis_client::next_epoch` / `is_current`。遅れて終わった接続が新しい接続を上書きし、コマンドが別のサーバーへ届くのを防ぐ）。ロックは `redis_client::lock` で取る（panic で poison したらセッションを捨てて回復する）。**Redis のコマンドと値はログに書かない**（MySQL の SQL の本文やクエリの結果と同じ扱い。`with_redis_session` を通るコマンドは `log::warn!` しない。接続の失敗だけは書いてよい）。キーの一覧（`redis_client::scan`）は、新しい一覧の要求が来たら SCAN のステップの途中で打ち切る（`next_scan_epoch` / `is_current_scan`。パターン欄の入力のたびに走るので、古い SCAN が接続を握り続けないように）。DB の切り替えの一覧は `redis_client::databases`（`CONFIG GET databases` が ACL で断られたら 16 とみなす。`INFO keyspace` にそれより大きい DB があればそこまで）、CLI の補完とヘルプは `redis_client::command_docs`（`COMMAND DOCS` の引数の定義から、ドキュメントと同じ記法の構文を組み立てる。Redis 7 より前のサーバーは名前だけ）。AI アシスト（`redis_ai_assist`）のプロンプトに添えるのは、版、DB 番号、キーの一覧の最初のページ（名前と型）だけ（`redis_client::ai_context`）。**値を読んで AI に送らないこと**（マニュアルの `docs/manual/ai-assist.md` が「値は送信しません」と約束している）。実サーバーでの確認は `just verify-redis`（試験用のキーを書き込んで消す）。
- **SQLite（#97）**: `src-tauri/src/sqlite_client.rs`（`rusqlite`、bundled で SQLite 本体を一緒にビルドする）。`Engine::Sqlite` は `Protocol::Sqlite` で、query 画面を MySQL と共用する。ファイルのパスは `MySqlConfig.file_path`（`sqlite_file`）に置き、`host` / `port` / `username` は空で書く（`engine` より古い版はこの 3 つが無いとストア全体を読めないので、項目自体は残す）。**パスはマシン固有**で、CA 証明書のパスと同じく同期ファイルに書かず、取り込みでもローカルの値を残す（`clear_machine_local_paths` / `carry_over_machine_local_paths`）。**存在しないファイルは開かない**（`sqlite_client::open` はファイルを作るフラグを付けず、先にファイルの有無を見る。打ち間違いで空の DB ができるのを防ぐため）。接続はタブごとに 1 本持ち続ける（`SqliteSession` / `TabConnection`。`run_sqlite_query` がタブの初回のクエリで開く）。画面は「すべて実行」を `;` で分けて 1 文ずつ送るので、接続を使い回さないと `BEGIN` / `COMMIT`、`PRAGMA`、一時テーブルが次の文に効かない。**クエリのたびに開き直す形に戻さないこと**。止めるのはタブの接続の `interrupt`（ほかのタブの文は止めない）。変更件数は、件数を変えない文（CREATE、BEGIN など）で前の DML の件数が残る `changes()` をそのまま返さず、`total_changes()` が動いたときだけ数える（`sqlite_client::run`）。セッションは `ConnectionCache` の `Backend` に置く（`use_sqlite_file`）。ウィンドウを閉じると接続が閉じ、開いたままのトランザクションはロールバックされる。資格情報の解決と SSH トンネルは通さない（`run_query` と `run_connection_test` が `Protocol::Sqlite` を先に分ける）。SQLite のプロファイルを保存すると、そのプロファイルの keyring のパスワード類を消す（`save_profile`。サーバーの種類から切り替えたときに残り、戻したときに黙って使われるのを防ぐ）。ログの扱いは MySQL と同じ（ファイルを開く失敗は書いてよい。文を実行した結果の `Err` は書かない）。Docker のラベルで `musql.engine=sqlite` と書かれたコンテナは一覧に出さない（`classify`。ファイルなので、コンテナに接続先が無い）。設定画面は `ui/settings.js` の `ENGINE_FIELDS` の `file` でファイルの欄だけを出す。
- **PostgreSQL（#96）**: `src-tauri/src/postgres_client.rs`（同期版の `postgres` クレートを `spawn_blocking` で呼ぶ。TLS は mysql と同じ native-tls で、SSL モードの意味も MySQL と同じ）。`Engine::Postgresql` は `Protocol::Postgres` で、query 画面を MySQL と共用する。資格情報の解決と SSH トンネルは MySQL と共用する。**接続はタブごとに 1 本持ち続ける**（`PostgresSession` / `TabConnection`、`run_postgres_query`。SQLite と同じ理由で、`BEGIN` / `COMMIT`、`SET`、一時テーブルを次の文に効かせるため。MySQL のように Pool から毎回借りる形にしないこと）。サーバーに閉じられた接続は、画面自身のクエリ（タブ無し）なら黙って張り直し、SQL タブなら 1 回エラーにして次の文で張り直す（`postgres_client::Reopen`。開いていたトランザクションが消えたことに気付かないまま、続く文がひとつずつ確定するのを防ぐため）。`RUNNING_QUERIES` への登録は接続のロックを取ってから行う（`run_postgres_query`。タブ無しのクエリは 1 本の接続とキーを共有するので、順番待ちの文が実行中の文の登録を上書きしたり消したりしないように）。SQL タブを閉じると、そのタブの接続を閉じる（`close_query_tab`。SQLite も同じ。PostgreSQL の接続はサーバーのプロセスを 1 つ使うため）。PostgreSQL に `USE` は無く、接続はデータベース単位なので、fingerprint にデータベースを含める（`connection_fingerprint`。DB を切り替えるとセッションが作り直される）。データベースが空なら dbname を送らない（サーバーがユーザー名と同じ名前のデータベースを選ぶ。psql と同じ）。文は simple query で送るので、値はすべてサーバーが書いたテキストで返る（MySQL のテキストプロトコルと同じ。bytea は `\x…`）。キャンセルは接続の `CancelToken`。**`postgres::Client` を async のタスクの上で drop しないこと**（自前の runtime で閉じるので panic する）。`TabConnection` の `Drop` が専用のスレッドへ渡して閉じている。エラーはサーバーの文面に、位置の行（psql と同じ `LINE N: …`。画面の `sqlErrorPosition` が読む）と DETAIL / HINT を付けて返す（`describe`）。NOTICE は `notice_callback` で捨てる（既定では info でログへ行き、データを含みうるため）。SSH 経由の `VERIFY_IDENTITY` は、`host` にプロファイルのホスト、`hostaddr` にトンネルの `127.0.0.1` を入れるので、証明書をプロファイルのホスト名で照合できる（`postgres_client::config`。`tunnel_tls` は `None`）。カタログは PostgreSQL 10 以降を前提にする（`relispartition`）。ログの扱いは MySQL と同じ（接続の失敗は書いてよい。文を実行した結果の `Err` は書かない）。実サーバーでの確認は `just verify-postgres`。
- **SSH 経由の `VERIFY_IDENTITY`（#133）**: SSH トンネルを通すと接続先は `127.0.0.1` になり、クライアントの TLS は証明書をその名前と照合してしまう。どちらのクレート（mysql、redis）も、接続先とは別の名前で照合する手段を持たない（postgres は `hostaddr` で照合の名前と接続先を分けられるので対象外。上の「PostgreSQL」の項）。Redis の TLS は接続の最初から始まるので、トンネルの側で張る（`tunnel_tls` → `redis_client::tunnel_tls`。照合するのはプロファイルの `host`。信頼済み証明書は `client` と同じく CA ファイルか Windows の証明書ストア）。トンネルを作るときに一度 TLS で接続し、証明書が合わなければその理由で失敗させる。クライアントはトンネルへ平文でつなぐ（`SshTunnel.tls_by_tunnel` → `redis_client::client` の引数）。MySQL の TLS はハンドシェイクの途中で始まるのでトンネルからは張れず、`tunnel_tls`（`connect_target` がトンネルを作る前に呼ぶ）が断って `VERIFY_CA` を案内する。**MySQL をトンネルの側の TLS で直そうとしないこと**（SSLRequest の差し込みとシーケンス番号の書き換えが要り、認証の流れも変わる）。`VERIFY_IDENTITY` 以外のモードはホスト名を照合しないので、SSH 経由でもクライアントの側で TLS を張る（`tunnel_tls` は `None` を返す）。プロファイルのホストが `127.0.0.1`（踏み台自身のサーバー）なら、クライアントの照合がそのまま正しいので、これも `None`。Docker の socat トンネルは対象外（コンテナの証明書は自己署名が普通）。
- **SSL モード**: `SslMode` enum（保存形式は `DISABLED` / `PREFERRED` / `REQUIRED` / `VERIFY_CA` / `VERIFY_IDENTITY`。serde は文字列を経由して読み書きする）。`PREFERRED` は、サーバーが TLS に対応していれば証明書を検証せずに TLS を使い、対応していなければ平文で接続する（MySQL の `PREFERRED`、libpq の `prefer` と同じ）。平文へ落とす条件はクライアントごとに違う。MySQL は `connect_mysql_pool` が、サーバーが TLS を持たない（`TlsNotSupported`）ときだけ TLS 無しで張り直す。Redis は `redis_client::open` が、接続する前に資格情報を付けない平文の `PING` を送り（`speaks_plain_resp`）、RESP（`+` か `-`）で答えたサーバーだけを平文で使う。それ以外（応答なし、TLS の alert、タイムアウト）は TLS のまま接続する。PostgreSQL は `postgres` クレートの `Prefer` に任せる。**平文へ落とす条件を「TLS の接続に失敗したら」に広げないこと**（TLS の失敗には、クライアント証明書の要求やタイムアウトなど、サーバーが TLS を持たない以外の理由があり、TLS を使えるサーバーへ平文で資格情報を送り直すことになるため）。Redis は選んだクライアントを `RedisSession` に持たせ、張り直しでも同じ方式を使う。未知の値は綴りを保ったまま `Unknown` として読み込み、`build_opts` が接続を断る（#131）。読み込みをエラーにしない（1 件の不正な値で全プロファイルと同期の取り込みが失敗するため）。`Disabled` に倒さない（TLS を黙って外すため）。綴りを捨てない（保存し直すと、同期ファイル経由で元の値を書いたマシンまで書き換わるため）。Docker のラベル（`parse_ssl_mode_label`）も同じ型で返す。
- **SSH**: `russh`（バージョンは `src-tauri/Cargo.toml` を正とする）。認証方式は公開鍵（`key`）またはパスワード（`password`）を選択可能。公開鍵: 指定鍵 → agent → デフォルト鍵。パスワード: `session.authenticate_password()`。タイムアウト 8 秒。ssh config 参照時は認証方式を公開鍵に固定。

## Docker 連携
- **Docker 連携**: `bollard` クレートで Docker API に接続（名前付きパイプ → TCP `127.0.0.1:2375/2376` フォールバック、WSL2 dockerd 対応）。running コンテナから MySQL と Redis と PostgreSQL のコンテナを自動検出する（#98。種類の判定は `classify`：`musql.engine` ラベル（ポートは `musql.port`、無ければ種類の既定。知らない値は `Engine::Unknown` のまま一覧に出し、ポートから推し量らない。`musql.engine` が無いときの `musql.port` は MySQL のポートとして読むので、既定外のポートの Redis には `musql.engine=redis` が要る）→ exposed port 3306（`musql.port` があればその番号）か `musql.enable=true` なら MySQL → 6379 なら Redis → 5432 なら PostgreSQL（#96）。Redis より前の版で MySQL として出していたコンテナを、Redis に変えないための順序。`DockerContainer.engine` に `Engine` で入れる）。開くときは `open_docker_window` が `Engine::window` でウィンドウを選び、`<label>:docker-open` を送る（知らない種類は開かない）。ports バインドなしのコンテナには `alpine/socat` 一時コンテナで TCP トンネルを作成（`auto_remove: true`、ラベル `musql.tunnel=true`）。トンネルコンテナは検出一覧から除外。アプリ起動時・終了時・接続の画面（query, redis）を閉じたときにトンネルをクリーンアップ。資格情報はコンテナ毎に保持（user/ssl_mode は localStorage、パスワードは keyring）。Cargo feature `docker`（デフォルト有効）で `bollard`/`futures-util` 依存を分離。
- **Docker のラベルカスタマイズ**: `musql.engine`（`mysql` / `mariadb` / `redis` / `postgresql`）/ `musql.name`（表示名）/ `musql.user` / `musql.password` / `musql.port` / `musql.ssl-mode` をコンテナのラベルに付けると、検出結果と資格情報の初期値に反映される。

## ウィンドウとメニュー
- **メニュー**: ハンバーガーボタン → `popup_menu()`。アクセラレータは非表示メニューバーで保持。項目は `MenuAction` enum（strum、#131）で、id は `<ウィンドウ>:<項目>`（`menu_id` / `parse_menu_id`）。**id の文字列を直書きしないこと**（組む側と `on_menu_event` の綴りの食い違いをコンパイルで止めるため）。ラベルは `menu_label` が英語と日本語を 1 つの腕で返す。項目を足したら、`MenuAction::windows`（どのウィンドウのメニューにあるか）と `MenuAction::rust_handler`（Rust で処理するならその処理、画面へ `menu:action` で渡すなら `None`）に足す。どちらも網羅的な `match` なので、足し忘れるとコンパイルが通らない。画面へ渡すなら、そのウィンドウのスクリプトの `menu:action` に `case` を足す。テスト `ui_scripts_handle_the_menu_items_they_are_sent` が、各画面のスクリプトの `case` と、その画面へ渡す項目が過不足なく一致するかを見る。
- **クリックで戻れる通知（#113）**: `src-tauri/src/toast.rs`。`tauri-winrt-notification` の `on_activated`（プロセス内のイベント）でバナーのクリックを受け、query ウィンドウを前面に出して `toast:activated` を送る。**プロトコル活性化（URL スキームで新しいプロセスを起こす方式。pike が採用）にしないこと**: 新しく起きたプロセスから、通知を出したインスタンスへ届ける手段が要るが、musql は多重起動を許していて single-instance を入れない。プロセス内で受ければ、通知を出したインスタンスが自分でクリックを受けるので、この問題が起きない。代わりに、通知センターへ移った後のクリックは受け取れない。**スタートメニューのショートカットに AUMID を書く**（無いとバナーが出ず、クリックも返らない）。初回の通知のときにだけ行う。どのショートカットを使うかは identifier から決める（ビルドの種類からは決めない。同じ AUMID のショートカットが 2 つできるのを避けるため）。**インストール版は NSIS の `muSQL.lnk` に書き足すだけで、無ければ作らない**（作ると、単体で実行した exe の置き場所を指す「muSQL」がスタートメニューに残る。消す主体がいない）。無いときは `toast_notify` が失敗を返し、画面側がクリックできない通常の通知に落ちる。**dev 版の `muSQL (dev).lnk` は毎回作り直してよい**（AUMID を登録するためだけのもので、リンク先の exe のパスが安定しない）。プロセスの AUMID は設定しない（`SetCurrentProcessExplicitAppUserModelID` を呼ばない。タスクバーのグループ化が変わるため）。通知は専用スレッド（COM の STA）で出し、**そのスレッドを終わらせないこと**（クリックの受け口は出したスレッドのアパートメントに属し、スレッドが終わると解放される）。表示とクリックはコードから確かめられないので、`just verify-toast`（`MUSQL_VERIFY_TOAST=1`）で実機確認する。
- **dev 版の目印（#120）**: dev 版は全ウィンドウのタイトル先頭に `[DEBUG]` が付く（pike と同じ表記）。判定は `is_debug_build`（`cfg!(debug_assertions)` または identifier の `.debug` 接尾辞。`tauri build --config tauri.dev.conf.json` は release プロファイルなので前者だけでは拾えない）。目印が示すのは「dev ビルドであること」で、状態の分離ではない（`--config tauri.dev.conf.json` 無しの `cargo tauri dev` は `[DEBUG]` が付くが、identifier は本番と同じでインストール版と状態を共有する）。`tauri.conf.json` の静的なタイトルは `setup` で付け直す。実行中にタイトルを変えるときは JS の `setTitle` ではなく `set_window_title` コマンドを呼ぶこと（目印を 1 か所で付けるため。capabilities から `core:window:allow-set-title` は外してある）。
- **ウィンドウ状態永続化**: `tauri-plugin-window-state`（常時有効）で main / query / redis のサイズ・位置・最大化を保存/復元。`StateFlags` は `SIZE | POSITION | MAXIMIZED` のみ（VISIBLE 等は除外＝show/hide パターンを上書きしない）。固定サイズの settings は `with_denylist(["settings"])` で除外。プラグインは `RunEvent::Exit` で自動保存するが、終了処理の `quit`（`main:exit` メニューと main ウィンドウの close）は `std::process::exit(0)` で終了しフックを飛ばすため、その直前で `app.save_window_state(StateFlags::all())` を明示呼び出ししている（この save を消すと状態が保存されない）。dev 起動は `tauri.dev.conf.json` で identifier を `.debug` に分離しているため、インストール版とウィンドウ状態は混ざらない。
- **仮想デスクトップの記憶（#126）**: `src-tauri/src/vdesk.rs`。main ウィンドウを、前回置いていた仮想デスクトップに開く（window-state プラグインはデスクトップを知らない）。**既定は OFF**（#144。起動したデスクトップから別のデスクトップへ移ると戸惑うため）。main の View メニューの「仮想デスクトップを記憶」（`MenuAction::RememberDesktop`。Rust が処理する）で切り替え、AppConfig の `remember_desktop` ファイル（`1` なら ON）に持つ。起動の直後に Rust が読むので localStorage には置かない。OFF のときは記録も復元もしない。ON と OFF のどちらへ切り替えても、先に `main_desktop` を消してから設定を書く（ON にしたとき、それより前に記録されたデスクトップ（常に記録していた #144 より前の版の分を含む）へ飛ばないように。消すのを先にするのは、失敗したときに設定を元のまま残すため）。**mutex は設定にかかわらず `setup` で取る**（`vdesk::claim`。OFF で起動したインスタンスが取らないと、そのあと ON で起動したインスタンスが自分を 1 つ目と誤判定して移ってしまう）。公開の COM API（`IVirtualDesktopManager`）で GUID を取り、AppConfig の `main_desktop` ファイルに書く（マシン固有なので同期しない）。記録は `quit` の `vdesk::on_quit`（全インスタンスが書くので、覚えているのは最後に閉じた muSQL の場所。main が隠れているときは、`CONNECTION_WINDOWS` のうち表示中のウィンドウのデスクトップを使う）、復元は `setup` の `vdesk::restore`。**戻すのは「ほかに muSQL が動いていないときに起動したインスタンス」だけ**（判定は identifier ごとの名前付き mutex）。多重起動を許しているので、全インスタンスを同じデスクトップへ飛ばすと、2 つ目を別のデスクトップで開けなくなる。mutex は `on_quit` で手放す（終了は Docker の後始末を数秒待つことがあり、その間に起動した muSQL が 2 つ目と誤判定されるため）。復元は `setup` で 1 回、500ms 後にもう 1 回試す（`setup` の時点ではシェルがウィンドウをまだ管理下に入れておらず、移動が失敗することがある）。**query、redis、settings のウィンドウには広げないこと**（クリックで開くものなので、押した場所から別のデスクトップへ消えると困る。pike も同じ理由でグローバルウィンドウの記憶を取り消した）。移したあとに `set_focus` を呼ぶのは、移動だけではデスクトップが切り替わらず、起動したのに何も出てこないように見えるため。覚えたデスクトップが消えていたら移動が失敗し、表示中のデスクトップに開く（作り直しは非公開 API の領分なので採らない）。
- **接続の画面（#98）**: プロファイルは種類に応じて query か redis のウィンドウで開く（`Engine::window`、`open_connection_window`）。開くときは `show_connection_window` が `<label>:<event>`（`query:open`、`redis:open`、`query:docker-open`）を送ってからウィンドウを出し、メイン画面を隠す。ほかの接続の画面（`CONNECTION_WINDOWS`）が開いていれば、`<label>:reset` を送って隠す（1 インスタンスで開ける接続は 1 つ。設定画面の「接続」からはメイン画面を経ずに開けるため）。2 つは `CONNECTION_WINDOWS` で、閉じるとき（× ボタンでもメニューの「ウィンドウを閉じる」でも）は `close_connection_window` が `<label>:reset` を送って隠し、メイン画面を出す。メニューの「ウィンドウを閉じる」と `vdesk::on_quit` も `CONNECTION_WINDOWS` を使う。接続の画面を足すときは、`CONNECTION_WINDOWS`、`tauri.conf.json`、capabilities の `windows`、メニュー（`show_popup_menu` と `setup_menus`）に足す。
- **ウィンドウ管理**: show/hide パターン採用。main 以外のウィンドウ（query, redis, settings）は `on_window_event` で `CloseRequested` を `api.prevent_close()` + `window.hide()` に差し替え、ウィンドウ破棄を防止。接続の画面（query, redis）を閉じるときの処理は「接続の画面」の項を参照。main ウィンドウの close はアプリ終了で、`CloseRequested` から `quit` を呼んで明示的に終わらせている（メニューの「終了」と同じ処理）。**この呼び出しを外さないこと**: 設定とクエリのウィンドウは非表示のまま残り、Tauri が自分で終了するのは全ウィンドウが無くなったときだけなので、外すと画面の無いプロセスが残り続ける（`just dev` が終わらない、1 時間ごとのアップデート確認が動き続ける、インストール版では exe が掴まれたままになる）。多重起動は意図的に許容している（1 インスタンスで同時に開ける connection は 1 つのため、複数接続は複数インスタンスで行う設計）。`tauri-plugin-single-instance` は導入しないこと。参考知見（[zenn.dev/sttk3/articles/69cb3bd6331325](https://zenn.dev/sttk3/articles/69cb3bd6331325)）:
  - `close()` はウィンドウを完全破棄、`hide()` はメモリ保持で非表示、`destroy()` はイベント発火なしで破棄。macOS では最後のウィンドウを `close()` するとアプリ自動終了するため main は `hide()` が安全（musql は Windows 専用だが将来のクロスプラットフォーム対応時に重要）。
  - macOS 11 で JS 側から `close()` を呼ぶとクラッシュする報告あり → close 処理は Rust 側で実行するのが安全。
  - `is_focused()` は Windows でウィンドウ生成直後にフォーカス判定が遅延する → 複数ウィンドウのアクティブ状態を正確に追跡するには `AppState` で `Focused` イベントをキャッチして明示管理する方が信頼性が高い。
  - close イベントの `listen` で close を再呼出しすると無限ループになる → `once` で1回限りのリスナーにするか、`prevent_close()` + `hide()` パターン（musql 現行方式）で回避。
  - フロントエンドでイベントリスナーを登録した場合、unmount 時に `unlisten` を必ず呼ぶこと（メモリリーク防止）。

  参考知見（同一スタックの pike での運用実績より）:
  - 開発版とインストール版を共存させるには、dev 用の設定ファイル（pike は `tauri.dev.conf.json`）で identifier を別（例: `.debug` サフィックス）に上書きする。window-state 系プラグイン等は identifier 単位で状態を保存するため、identifier が同一のままだと開発版とインストール版で状態が混ざる。導入時はセットで検討する。
  - 素の `listen()`（`@tauri-apps/api/event`）はデフォルト target が `Any` のため、Rust が `emit_to(label, …)` で特定ウィンドウ宛てに送ったイベントでも全ウィンドウで発火する。特定ウィンドウだけで処理したいイベントは `getCurrentWindow().listen()`（target = 自ラベル）で受けること（pike で全ウィンドウが同一ファイルを開こうとする不具合の原因になった）。全ウィンドウにブロードキャストして ID でフィルタする方式とは使い分ける。


## TablePlus からの取り込み（#99）
- `src-tauri/src/tableplus.rs`。`%LOCALAPPDATA%\com.tinyapp.TablePlus\Data`（`Setting.json` の `sharedConnectionPath` があればそちら）の `Connections.plist` と `ConnectionGroups.plist` を読み、`ExportData` に変換する。キーは macOS 版と同じで、TLS モードの番号の並び（`ssl_mode`）は TablePro の取り込み処理に合わせてある。取り込みは `import_tableplus` コマンドで、衝突の検出と追加は JSON のインポートと共通の `merge_import` を通る（1 回目の呼び出しで重複を返し、2 回目は TablePlus を読み直す）。
- **パスワードは読まない**。Windows 版は独自の形式で `.tpmaster` に暗号化して保存し、その鍵を資格情報マネージャー（`TablePlus`）に置いている。取り込んだプロファイルは `save_password` / `save_ssh_password` を false（都度入力）にする。TablePlus で「パスワード無し」（`*PasswordMode` が 2）の接続だけは true にする。秘密鍵のパスフレーズは true のまま（鍵にパスフレーズがあるか分からず、毎回の入力を求めると無い鍵の利用者の邪魔になるため）。
- TLS の「Preferred」は `PREFERRED`、PostgreSQL の「allow」は muSQL に無いので、いちばん近い `PREFERRED`、知らない番号は `REQUIRED` にする（TLS を黙って外さないため）。番号が無ければ TablePlus の既定（各ドライバーの選択肢の先頭）とみなす。秘密鍵はファイル名だけが入っているので `%USERPROFILE%\.ssh` から探し、無ければ空にする（agent と既定の鍵に落ちる）。muSQL のグループは入れ子にできないので、入れ子のグループは「親 / 子」の名前にする。対応しない種類の接続は `skipped` で画面に返す。既存のプロファイルを上書きするときは、TablePlus が知らない設定（パスワードの保存方式と 1Password の参照）を既存の側から引き継ぐ（`keep_local_settings`。消すと同期先のマシンでも消えるため）。
- 手元の TablePlus で読めるかは `cargo test tableplus -- --ignored --nocapture` で確かめる（件数と種類だけを出す）。

## 設定の同期とアップデート
- **接続プロファイルの外部同期（#47）**: 指定パス（Dropbox 等）の JSON にストアをミラーし複数マシン共有。同期パスは AppConfig `sync_path`（環境依存＝非同期）。**書き出しは `save_profiles` 内で自動ミラー**（全ウィンドウの変更を捕捉、同期的なので focus 取り込みと競合しない）。書き出しはシークレット除去（`sanitized_store_json`。パスワード/SSH 秘密は `skip_serializing` で元々出ないが二重防御）。**取り込み** `sync_import`（`refreshProfiles` が起動時/フォーカス時/`profiles:changed` で呼ぶ）は id ベース merge（規則は次の項の `merge_sync`。ローカル固有は保持・削除は非伝播）、読み取り/parse 失敗はローカルへフォールバック、差分時のみ保存、async+spawn_blocking（クラウド placeholder のフリーズ回避）。UI は main メニュー `main:sync-settings` → `openSyncModal`。コマンド: `get_sync_path`/`set_sync_path`/`sync_import`/`sync_export`/`pick_sync_path`/`sync_folder_candidates`。
- **同期フォルダの検出と安全な書き込み（#143）**: `src-tauri/src/sync_folder.rs`。`sync_folder_candidates` が OneDrive（環境変数 `OneDriveConsumer` / `OneDriveCommercial` / `OneDrive`）と Dropbox（`info.json`）のフォルダを返し、画面はそれを選択肢に出す（選ぶと `<フォルダ>\muSQL\profiles-sync.json`）。Google ドライブは載せない（ドライブ文字と「マイドライブ」の名前が環境で変わり、確かめられないため）。**同期ファイルは `write_atomic`（同じフォルダの一時ファイルに書いてから置き換える）で書く。`std::fs::write` で直接上書きしないこと**（書きかけのファイルが送られる）。**書く前に読み直し、前回読み書きした内容（`SyncBaseline`。メモリだけに持ち、起動直後の取り込みで埋まる）から変わっていたら、先に取り込んでから書く**（`push_to_sync_locked`）。取り込み（`merge_sync`）は、前回から相手が変えていないプロファイルには手を付けない。両方が変えたものは、書くときは手元（保存したばかりの値）、取り込むときはファイルを優先する。前回の内容が無いとき（起動直後）は、取り込みはファイル優先、書き込みは手元を残して足りないものだけを足す。削除は伝えない（前回から相手が変えていなければ、手元で消したものは戻らない）。同期ファイルの読み書きはすべて `SYNC_STATE` のロックの中で行う。**ロックを持ったまま `save_profiles` を呼ばないこと**（ミラーがロックを取り直して止まる。ロックの中では `write_local_profiles` を使う）。`sync_import` はファイルの読み込みをロックの外で済ませる（クラウドのダウンロード待ちの間、保存を止めないため）。ローカルのストアはロックの中で読む（`load_profiles_for_sync`。ロックの前に読むと、その間の保存が消える）。同期パスもロックの中で読み直す（`set_sync_path` もロックを取り、パスが変わったときだけ前回の内容を捨てる）。競合コピー（`conflict_copies`。OneDrive の `profiles-sync-PC名.json`、Dropbox の「競合コピー」）は `sync_import` が取り込み、書き出せたら消す。競合コピーはいつの内容か分からないので、手元に無いプロファイルとグループを足すだけで、既存のものは上書きしない。**名前の判定（`conflict_copy_matcher`）を広げないこと**（一致したファイルは消すので、手で作ったバックアップ（`- コピー`、`(1)`、`-old`）に当たらないよう、OneDrive の PC 名と Dropbox の「conflicted copy」「競合コピー」だけを見る）。加えて `app_version` を持つ同期ファイルだけを対象にし、新しい版が書いたもの（#81）は取り込まずに残す。
- **アップデート**: `tauri-plugin-updater` + Ed25519 署名。起動 3 秒後と、以後 1 時間ごと（`UPDATE_CHECK_INTERVAL`、#114）に自動チェック + Help メニューから手動チェック。確認は `fetch_update` に集約してあり、`check_update` が結果を必ず画面へ知らせる（あれば `update-available`、無ければ `update-none`）。main 画面のバナーは確認のたびに最新の結果へ置き換わる（インストール中は触らない）。**確認に失敗したときはイベントを出さない**（先に見つけた更新の表示を残すため）。Cargo feature `self-updater`（デフォルト有効）で分離。`--no-default-features` で Store ビルド（アップデータ無効）。
