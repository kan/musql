# 1Password 連携

パスワードの保存先は Windows 資格情報マネージャー（keyring）のままで、その**初期値と更新元**として 1Password を使えます。複数マシンで同じプロファイルを使うとき、マシンごとにパスワードを手入力する手間がなくなります。

## 仕組み

muSQL は接続のたびに 1Password を見にいくわけではありません。参照するのは次の順です。

1. 都度入力のプロンプトに入力した値
2. Windows 資格情報マネージャー（keyring）に保存された値
3. **1Password**（1 と 2 のどちらにも無いときだけ）

3 で取得した値は、その場で資格情報マネージャーに保存されます。以降はそこから読まれるため、1Password が呼ばれるのは**マシンごとに 1 回だけ**です（「キーリングに保存」がオンの場合。オフのときは保存先が無いため、そもそも 1Password 連携は使いません）。

この設計には理由があります。Windows では 1Password CLI の認証が呼び出し元プロセス単位で行われるため、接続のたびに 1Password を叩くと毎回 Windows Hello の確認が出てしまいます。

保存されるのは `op://vault/item/field` という**参照文字列だけ**で、パスワードそのものではありません。参照文字列は [接続の同期](sync.md) の対象に含まれます。同期先のマシンでは、最初の接続時に 1Password から自動で取得されます。

## 準備

1. [1Password CLI](https://developer.1password.com/docs/cli/get-started/)（`op`）をインストールする
2. 1Password 8 デスクトップアプリの **設定 → 開発者 → 「1Password CLI と連携」** を有効にする
3. muSQL を再起動する

`op` が見つからない場合、1Password の入力欄は表示されません。

## 設定

設定ウィンドウのパスワード欄の下に、1Password の参照を入れる欄が出ます。MySQL パスワード / SSH パスフレーズ / SSH パスワードのそれぞれに設定できます。

**`…` ボタンから選ぶ**（推奨）

1. **`…`** を押すと 1Password のアイテム一覧が開きます
2. 検索欄に打ち込んで絞り込み、目的のアイテムを選ぶ
3. そのアイテムのフィールド一覧から、使うフィールドを選ぶ
4. 参照が欄に入り、**続けてパスワードの取得まで自動で実行されます**
5. **保存** すると、取得した値が資格情報マネージャーに格納されます

アイテム一覧は最初の1回だけ 1Password から読み込み、以降はアプリを閉じるまで再利用します。1Password 側でアイテムを追加した直後などは「**再読み込み**」を押してください。

なお、このアイテム一覧に秘密情報は含まれません（アイテム名・vault 名・分類のみ）。フィールド一覧のほうは 1Password CLI が値も返しますが、muSQL は**画面に渡す前に値を捨てています**。選択画面に出るのはフィールド名と参照文字列だけで、値が保存されることもありません。

**手で貼り付ける**

1. 1Password アプリで対象のフィールドを右クリック →「**シークレット参照をコピー**」
2. muSQL の 1Password 欄に貼り付ける（`op://Employee/prod-db/password` のような形式）
3. **保存**

この欄は「**キーリングに保存**」がオンのときだけ表示されます。都度入力にしている場合は、接続前のプロンプトで手入力する運用になるため、1Password 連携の出番がありません。

SSH の参照も同様に、**SSH が有効で、かつその認証方式を選んでいるとき**にだけ使われます。認証方式を公開鍵からパスワードへ切り替えた場合、使われなくなった側の参照は無視されます。

参照を設定しただけではパスワードは取得されません。次にそのプロファイルで接続したときに取得され、資格情報マネージャーに保存されます。

## パスワードを最新の値に更新する

1Password 側でパスワードを変更したときは、資格情報マネージャーに古い値が残っているため、自動では追随しません。設定ウィンドウで **`1P` ボタン** を押すと、その場で 1Password の最新の値を取得してパスワード欄に入れます。あとは **保存** すれば資格情報マネージャーが更新されます。

参照を選び直した場合は取得まで自動で走るので、このボタンを使うのは「参照はそのままで値だけ新しくしたい」ときです。

## AI の API キー

[AI アシスト](ai-assist.md) の API キーにも同じ仕組みが使えます。AI 設定モーダルの API キー欄の下に 1Password の参照欄があります。

接続プロファイルと違い、AI の設定はマシンごとの設定なので**同期されません**。マシンごとに参照を設定してください。

## うまくいかないとき

エラーメッセージは 1Password CLI が返したものをそのまま表示します（英語）。

- **1Password の欄が出てこない** — `op` が見つかっていないか、「キーリングに保存」がオフです。`op` をインストールした場合は muSQL を再起動してください。
- **アイテム一覧の読み込みが遅い** — Windows 版の 1Password CLI はローカルキャッシュを持てないため、一覧の取得は毎回サーバーとの通信になり 10 秒ほどかかります（アイテム数にはほとんど依存しません）。muSQL 側でアプリを閉じるまでキャッシュするので、2 回目以降は即座に開きます。デスクトップアプリの承認を求められた場合は、その待ち時間も加わります。
- **参照が `op://` で始まっていない、という趣旨のエラー** — 形式が違います。1Password アプリの「シークレット参照をコピー」で取得した文字列を貼り付けてください。
- **`isn't a vault in this account`** — vault 名か item 名が違います。vault 名を含む完全な参照になっているか確認してください。
- **Windows Hello の確認が出る** — デスクトップアプリ連携による認証です。承認すればそのまま取得に進みます。
- **パスワードが古いまま** — 資格情報マネージャーに保存済みの値が使われています。上記の `1P` ボタンで更新してください。
